# Changes

## 0.1.0 [xxxx/xx/xx]

**New Features:**

- First version of Juntei, a Windows forensics artifact parser. (@YamatoSecurity)
- `parse-amcache` command: parses `Amcache.hve` (modern Windows 10/11 and legacy Windows 8/8.1/Server 2012 R2 schemas) with Yamato Security's ys-amcache-parser: inventoried executables with SHA-1, PnP devices, and findings for system binaries outside `System32` and executables in staging directories. One file (`-f`) or every Amcache hive under a directory (`-d`); output to the terminal or saved as text, JSON, JSONL or CSV tables (`-o`, `-t`), with a Hayabusa-style progress bar and results summary. (@YamatoSecurity)
- `parse-mft` command: parses `$MFT` with Yamato Security's ys-mft-parser (a fork of Omer Ben-Amram's mft crate): a CSV with the columns of Eric Zimmerman's MFTECmd, computed as MFTECmd computes them: one row per file name and per alternate data stream, with the parent path, both sets of timestamps, USN, LSN, security ID, flags, name type, reference count, reparse target, object ID, logged utility stream, `Zone.Identifier` contents and the timestomping indicators `SI<FN`, `uSecZeros` and `Copied`, and MFTECmd's `--at`, `--sn` and `--cutoff` as `--all-times`, `--short-names` and `--cutoff`. `-t mft-dump-csv` (one row per entry: full path with `\` separators and the long names from extension records, flags, sizes, timestamps to 100 ns including the MFT-modified times, alternate data streams) and JSON / JSONL (every attribute and the full path) are the same output as ys-mft-parser's `mft_dump` command. One file (`-f`) or every `$MFT` under a directory (`-d`), entry ranges (`-r`), resident `$DATA` stream extraction (`-e`), a progress bar over the entries and a summary of in-use, deleted and damaged entries. Damaged or crafted records (a parent-reference loop, an unusable first record, malformed data runs) do not crash the run. (@YamatoSecurity)
- `parse-prefetch` command: parses Prefetch files (format versions 17 to 31, Windows XP to 11, including compressed files) with Yamato Security's ys-prefetch-parser (a fork of Samuel Garcés Marín's frnsc-prefetch whose output matches libscca): one CSV row or JSON / JSONL object per file with the executable path, prefetch hash, run count, last 8 run times, volumes, directories and loaded files with NTFS file references, or one record per execution sorted by time (`-T`). Findings for Windows system binaries loaded from outside `System32` (high) and executables run from staging directories (medium). One file (`-f`) or every `*.pf` under a directory (`-d`), with a progress bar and a summary. (@YamatoSecurity)
- `parse-usn-journal` command: parses the NTFS USN change journal (`$UsnJrnl:$J`) with Yamato Security's ys-usn-journal-parser (a fork of sootmark-usn): every V2/V3 record (V4 range-tracking records in JSON), with the path each record's directory had at the time, rewound from the journal and seeded from the volume's `$MFT` (`-m`, or found next to `$Extend`). CSV with MFTECmd's `$J` columns, or every field as JSON / JSONL; `--carve` finds records in disk images and unallocated space. One file (`-f`) or every `$J` under a directory (`-d`), a byte progress bar and a summary of record versions, time range, creates / deletes / renames, unresolved paths and damaged data. (@YamatoSecurity)
- `parse-srum` command: parses the System Resource Usage Monitor database (`SRUDB.dat`; tested on Windows 10, 11 and Windows Server 2022) with Yamato Security's ys-srum-parser (a fork of Sootmark's ese and srum crates): every entry of every provider table, with programs, accounts, FILETIME columns and network interface types decoded as SrumECmd decodes them, as one CSV table per provider named as SrumECmd names them (plus `SruDbIdMapTable.csv`) or one JSON / JSONL object per entry. Account and Wi-Fi network names from the SOFTWARE hive (`-r`, or found in the same collection), read with a small bounds-checked hive reader. One file (`-f`) or every `SRUDB.dat` under a directory (`-d`), a progress bar and a summary of entries per table, time range, bytes sent and received and the top senders. (@YamatoSecurity)
- `parse-lnk` command: parses Windows shortcuts (`*.lnk`) with Yamato Security's ys-lnk-parser (a fork of Sootmark's shell crate): one CSV row per shortcut with LECmd's columns (target times, size, attributes and MFT reference, volume or network share, arguments, the target item path, the machine name, MAC address and droids of the tracker block, the extra data blocks present) plus icon, hotkey, known and special folder, Darwin, shim layer, network provider and console code page columns, or every field (target items, property stores, console settings) as JSON / JSONL. ANSI text in the code page of the system that made the link (`--code-page`, e.g. 932). Findings for arguments hidden inside string data that claims more than 260 characters (read as Windows reads it), data appended after the link and shells or script hosts started with arguments. One file (`-f`) or every `*.lnk` under a directory (`-d`), a progress bar and a summary of target drive types, machines, time range and damaged links. (@YamatoSecurity)
- `parse-jump-lists` command: parses Windows jump lists with Yamato Security's ys-jump-lists-parser (from Sootmark's shell crate's jump list and compound file code, with links read by ys-lnk-parser): automatic jump lists (every `DestList` version, Windows 7 to 11, including files that end inside their last sector) and custom jump lists, as JLECmd's two CSV tables (`AutomaticDestinations.csv` with every `DestList` entry and its link, plus link streams no entry names; `CustomDestinations.csv` with every category's links) and more columns, or every field as JSON / JSONL (the `DestList` header, entries' property stores, the `DestListPropertyStore`, custom categories). Application names from Eric Zimmerman's AppID list; links left over from an earlier version of a custom list are recovered. One file (`-f`) or every jump list under a directory (`-d`), a progress bar and a summary of applications, machines, last-used range and target drives, with findings for leftover links, unlisted link streams, items staged for a CD or DVD burn and shells or script hosts started with arguments. (@YamatoSecurity)
